# Maintaining Shipyard

## Repository shape

`agents/` holds generic role prompts, runners, and shared shell code.
`skills/` holds the project-installable workflows. `dashboard/` owns the
private operator view. `scripts/` contains installer and maintenance tools;
`tests/` supplies automated coverage.

Read [CLAUDE.md](../CLAUDE.md) for the repository’s development gates and
working conventions. Project-local agent instructions are in
[AGENTS.md](../AGENTS.md).

## Public deck

The deck is published from `docs/` at `/shipyard/`. A configured pre-push
mirror can publish the same generated bytes to `/writing/the-shipyard/` in the
separate `wabbazzar.github.io` checkout.

The mirror is off until `[deck] mirror_dir` in `.agents/config.toml` (or
`DECK_MIRROR_DIR`) identifies that checkout. Run it manually with:

```bash
scripts/sync-deck-mirror.sh [<sha>]
```

It exits `0` when pushed, `2` for an invalid configuration or guard, and `3`
when no mirror is configured or the bytes are unchanged. Public behavioral
claims should update the existing deck editorial rather than create a parallel
explainer.

## BopBop pack

The `pack.toml` manifest makes Shipyard available as a BopBop context pack:

```bash
bopbop pack install https://github.com/wabbazzar/shipyard
```

This exposes context and controls; it does not install a crew on any project.
Crew installation remains an explicit `install.sh --project …` action.
